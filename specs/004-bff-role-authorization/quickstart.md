## 2. Manual validation (local)

```bash
podman compose -f compose.yaml -f compose.dev.yaml up -d
# $INTERNAL_BFF_TOKEN: client-credentials token of a Keycloak client ("bff") holding the internal-access role
# $PARTNER_BFF_TOKEN: client-credentials token of a Keycloak client ("nox-bff") holding the partner-access role
# $ACTING_USER_ID: an internal (Owl) user id, UUID format, that already owns at least one partner link

# 1. Internal BFF lists a person's links, acting for them via X-User-ID
curl -s http://localhost:8080/api/v1/user-partner-links \
  -H "Authorization: Bearer $INTERNAL_BFF_TOKEN" -H "X-User-ID: $ACTING_USER_ID" | jq .

# 2. Same call without X-User-ID -> 400
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/v1/user-partner-links \
  -H "Authorization: Bearer $INTERNAL_BFF_TOKEN"

# 3. Same call with the partner BFF's token -> 403 (wrong permission for this surface)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/v1/user-partner-links \
  -H "Authorization: Bearer $PARTNER_BFF_TOKEN" -H "X-User-ID: $ACTING_USER_ID"

# 4. Partner BFF still reads link-request/link-query endpoints as before
curl -s http://localhost:8080/api/v1/partner-links/<linkId> \
  -H "Authorization: Bearer $PARTNER_BFF_TOKEN" -H "x-service-id: demo-partner" | jq .

# 5. Internal BFF attempting a partner-only endpoint -> 403
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/v1/partner-links/<linkId> \
  -H "Authorization: Bearer $INTERNAL_BFF_TOKEN" -H "x-service-id: demo-partner"

# 6. The retired /me prefix is gone -> 404 (authenticated, but no handler)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/v1/me/partner-links \
  -H "Authorization: Bearer $INTERNAL_BFF_TOKEN" -H "X-User-ID: $ACTING_USER_ID"
```

Expected: steps 1 and 4 return the same shapes as before this feature (no payload change, only
who may call and, for step 1, a new prefix); step 2 returns `400`; steps 3 and 5 return `403`;
step 6 returns `404`; the application log shows one `accessDenied` structured event for each
`403`, and none for step 6 (no authorization decision is involved in an unmapped path).
